# Adopt Kioku 0.9.1.0 bounded reads

This candidate adds compatible Session/Memory facades and migration 0014;
existing call signatures remain. The composed plan now contains 61 entries
(15 Kiroku, 32 Keiro, 14 Kioku). Keep previously applied migration bytes and
checksums intact. No new upstream cohort edge is required.

Apply the embedded plan before new hosts start. Reconcile Kioku read-model
registrations through `Kioku.ReadModel.reconcileReadModelRegistry`. Drain old
hosts, preview the compiled `Kioku.ProjectionCatalog.kiokuProjectionCatalog`
with `Keiro.ReadModel.Rebuild.previewCatalogAdoption`, review both changed
live groups and adopt them with `adoptCatalogGroups`. Ordinary registration
fails closed on catalog drift. Do not update framework tables by hand or
rebuild existing projections merely to add read-only query registrations.

Use context-first `getPageWithContext` and scalar `getCountsWithContext`
facades when an unbounded read is inappropriate. Memory target selection must
name exact scope or namespace-wide scope explicitly. Bind transport cursors
to the parent, collection, filters and memory space around the shared Relay
cursor. Full details and orders are in `docs/user/bounded-reads.md` in
`mori://shinzui/kioku` (artifact-level source/document URI pending).

For rollback, drain new hosts and preview/adopt the old compiled catalog
through the same public lifecycle. Leave additive indexes and migration ledger
entries intact. Do not claim publication or consumer adoption before release.

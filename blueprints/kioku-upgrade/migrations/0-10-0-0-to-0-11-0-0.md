# Adopt Kioku 0.11.0.0 fixed Memory reads

This edge covers `mori://shinzui/kioku` 0.10.0.0 to 0.11.0.0. All five
packages move together; upstream dependency bounds are unchanged, so this edge
entails no upstream migration edge.

Inspect the consumer's Memory selection call sites. `MemoryFilter` gains a fifth
field, `scopeKind :: Maybe ScopeKind`. Append `Nothing` to positional construction
and set the field explicitly in record construction to retain existing selection.
Set `Just kind` only when the caller wants the intersection of that kind with its
explicit target. Exact global plus a kind, or an exact entity of a different kind,
is empty. Never widen the target to make a mismatch return rows.

For bounded Memory resources, prefer the permission-checked facades
`getMetadataWithContext`, `getMetadataPageWithContext`, `getTagsPageWithContext`
and `getNewestActiveMetadataWithContext` from `Kioku.Memory`. Metadata contains
complete scalar fields and `tagCount` instead of the tag collection. Tags are
separate complete values ordered by numeric stored-array ordinal. Missing/foreign
parents return `Nothing`; existing empty parents return `Just` an empty Connection.
Archived metadata and tags remain visible. The maximum page size remains 100.
Restart tag traversal after replacing tags; bind host transport cursors to resource,
parent, filters and space, adding a revision only if the host requires rejection
of stale cursors. Do not treat a numeric cursor as a snapshot.

Use newest-active for recency: it ignores priority, sorts creation time descending
and ID ascending, and intersects optional status. An explicitly non-active status
returns absence. Ordinary priority lists, session-filtered recency lists and
ascending supersession chains keep their orders. Complete counts use the same
filter intersection. Preserve permission denial, page validation, read-model
failure and the outer Store failure channel as errors rather than empty results.

The composed migration plan grows from 61 to 62 entries (15 Kiroku, 32 Keiro,
15 Kioku). Migration `0015-active-memory-recency.sql` adds an active-only index in
one transaction. It takes a SHARE lock on `kioku.memories`: reads continue but
writers wait for commit. Do not change any previous migration bytes or ledger
checksums. An operator chooses the maintenance window for a data-bearing database.

Four query registrations change only the memory group's catalog fingerprint.
Drain old hosts, preview adoption using the new complete validated host catalog,
select the affected Kioku memory group, adopt through public
`previewCatalogAdoption` / `adoptCatalogGroups`, then start/register normally.
`withNoopAppEnv` registers before its callback: adoption inside that callback is
too late. Use the administrative `AppEnv` / `noopTracer` / `runAppIO` recipe at
`mori://shinzui/kioku` with project-relative path `docs/user/bounded-reads.md`
(artifact-level URI pending). A composed host must use its complete catalog,
not replace it with a Kioku-only catalog. Registry reconciliation alone does not
adopt catalog drift. Retain typed lifecycle errors. Rollback likewise drains hosts
and uses the old compiled catalog's supported adoption; leave additive indexes.

Build and run the consumer's focused Memory tests. Prove kind intersections/counts,
priority versus recency, tag-parent absence, archived visibility, page validation
and denial-before-Store behavior for the host's routes. Use the published release;
no local dependency override is a completed adoption. Do not add Rei-specific
routes or host vocabulary to Kioku.

# Adopt Kioku 0.10.0.0 gated bounded reads

This release changes only the six bounded reads that 0.9.1.0 added. Their
0.9.1.0 form never checked the `MemoryAccessContext` it was given, so a context
authorized only for `MemoryRecord` or `MemoryForget` could list and count its
whole memory space. 0.10.0.0 closes that. 0.9.1.0 was never published to
Hackage; a project coming from Hackage 0.9.0.2 crosses the 0.9.1.0 edge first,
then this one. No migration, SQL, checksum, catalog fingerprint or read-model
identity changes: the composed plan stays at 61 entries and no further catalog
adoption is needed. No upstream cohort edge is entailed.

Find every call site, in `Kioku.Session` and `Kioku.Memory` alike:

```sh
rg -n 'get(Page|Counts|TurnsPage|Relations)WithContext|BoundedPageError|SessionFilter' --type haskell
```

1. **Result types.** All six (`Session.getPageWithContext`,
   `getCountsWithContext`, `getTurnsPageWithContext`, `getRelationsWithContext`;
   `Memory.getPageWithContext`, `getCountsWithContext`) now return
   `Either BoundedReadError a`. Replace the nested
   `Either ReadModelError (Either BoundedPageError a)` handling with one match
   on `BoundedReadNotPermitted`, `BoundedReadFailed ReadModelError` and
   `BoundedReadInvalidPage BoundedPageError`. Both modules re-export the type.
   Map `BoundedReadNotPermitted` to the project's authorization failure, not to
   a server error or an empty page.

2. **`SessionFilter.status`** is a `SessionStatus` (`StatusRunning`,
   `StatusAwaiting`, `StatusCompleted`, `StatusFailed`, `StatusInteractive`),
   not `Text`. Parse transport input with
   `Kioku.Session.ReadModel.parseSessionStatus` and reject an unknown status
   at the boundary instead of passing it through.

3. **The permission gate is not visible to the compiler.** Steps 1 and 2 are
   type errors; this one is not. A call that builds its context with
   `authorizeMemoryAccess` for record or forget only, and then reuses that
   context for a bounded read, still compiles and now fails at runtime with
   `BoundedReadNotPermitted MemoryRead`. For every call site found above, trace
   where its context was authorized and confirm `MemoryRead` was requested.
   Do not treat a passing build, or a passing suite that only uses
   all-permission contexts, as evidence that this step is done.

The gate runs before page validation, so a refused context reports
`BoundedReadNotPermitted` even when the page size is also invalid. A zero-size
page is valid and returns only page info; the page limit is exported as
`Kioku.Pagination.maxBoundedPageSize`. Full details are in
`docs/user/bounded-reads.md` in `mori://shinzui/kioku` (artifact-level document
URI pending).

Rollback is a source revert only. No database state changed in this window.

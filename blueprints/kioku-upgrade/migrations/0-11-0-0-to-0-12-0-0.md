Kioku packages and internal bounds together. Follow the entailed
mori://shinzui/keiro/templates/keiro-upgrade 0.21.0.0 → 0.22.0.0 edge;
upstream guidance entails the Kiroku cutover once.

Find dependency sources through Mori and resolve released packages: Keiro/core/
migrations/test-support 0.22.0.0, Kiroku Store 0.12.0.0, Store migrations
0.7.2.0, Shibuya Core 0.12.0.0 and Kiroku adapter 0.7.0.0. Preserve the host's
AI grants and typed SQLSTATE/decode failure classification. A complete hand-built
`Ingested` now supplies `deliveryStatus = pure DeliveryCurrent`; normal
constructors already do so. Inspect exhaustive subscription-target matches.
Keep `Category` exact; namespace subscriptions are a separate opt-in capability.
Do not introduce DSL, HTTP operations, or queue dependencies for a Kioku-only host.

The native plan becomes 63 entries: 16 Kiroku, 32 Keiro and 15 Kioku. From a
complete previous cohort, only `kiroku/0016` applies. It replaces two subscription
constraints and the Kiroku schema comment without changing event, checkpoint or
binding values. Do not rewrite historical SQL or checksums. No catalog adoption
is needed for a valid 0.11 host. If the database is older, enumerate every missing
migration and follow its own runbook before accepting this allowance.

An operator must retain identified old/new artifacts and rehearse a verified
backup on dedicated scratch databases with the deployed PostgreSQL major. Stop
affected workers and writers/embedded hosts, run the host-owned composed runner
(`kioku-migrate up` for a Kioku-owned installation), verify and repeat as a no-op,
then start new Store-linked hosts. Do not automatically migrate real data while
applying this source edge. After namespace bindings or new writes, source rollback
alone does not establish downgrade safety; prefer reviewed forward repair.

Build and test the host with the released cohort. Prove historical native decode,
space isolation, catalog registration, timer atomicity and actual embedding
checkpoint/delivery after restart. Run the restored-history replay/rebuild/write
comparisons described at mori://shinzui/kioku plus project-relative
`docs/user/upgrading-to-keiro-0-22.md` (artifact URI pending). Report missing
archive/deployment evidence as pending, and keep activation separate from source

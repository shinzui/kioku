# Kioku 0.13 to 0.14

Align all Kioku packages used by the host at 0.14.0.0. Rebuild the host, CLI,
workers and migration executable against the resolved cohort in
`files/kioku-cohort-versions.md`. Confirm any direct upstream integrations
have completed the entailed adapter and Keiro edges.

Rehearse the host's composed migration runner on a restored clone. From a
complete Kioku 0.13 baseline, expect 64 applied entries and only `keiro/0033`
pending in the Kioku plan. Run `up`, then `status` and `verify`. Expect 65
applied entries (17 Store, 33 Keiro, 15 Kioku) and zero pending or unknown.
A second `up` must apply zero migrations. Include any host-owned components
in the totals. Check that a timer scheduled before the upgrade can still fire.

For persistent deployments, the operator quiesces hosts and workers, takes a
backup, applies and verifies the plan, then starts the rebuilt workers.
Existing timer and workflow rows may carry NULL trace fields.
The embedding subscription now links a new processing trace to the writing
span when an event carries a valid traceparent. Update host queries that
select processing spans by name to match `process <processor>`.

# Adopt Kioku 0.12.0.1 and the Baikai 0.10 cohort

This edge covers mori://shinzui/kioku 0.12.0.0 → 0.12.0.1. It applies to a host
whose dependency closure includes Core, CLI or the migration executable. An
API-only consumer aligns its Kioku version and retains its existing wire types.

Find dependency sources and documentation through Mori. Align the Kioku packages
the host uses at 0.12.0.1. When the host directly constrains these AI packages,
align those bounds with the released cohort:

- mori://shinzui/baikai/packages/baikai: `^>=0.10.0.0`.
- mori://shinzui/baikai/packages/baikai-claude and
  mori://shinzui/baikai/packages/baikai-openai: `^>=0.7.3.0`.
- mori://shinzui/baikai/packages/baikai-effectful: `^>=0.4.0.5`.
- mori://shinzui/shikumi/packages/shikumi: `^>=0.4.1.1`.
- mori://shinzui/shikumi/packages/shikumi-trace: `^>=0.3.0.2`.

The released Shikumi, Cache and Trace packages still declare Baikai upper bounds
below 0.9. Kioku's repository-level exceptions are absent from Hackage source
archives and are not inherited by consuming projects. Add these scoped entries
to the host's `cabal.project`, preserving its existing exceptions:

```cabal
allow-newer:
  shikumi:baikai
  , shikumi-cache:baikai
  , shikumi-trace:baikai
```

Keep the qualified migration cohort explicit in that project too:

```cabal
constraints:
  kiroku-store-migrations ==0.7.2.0
```

Merge with existing fields instead of replacing unrelated constraints. Version
0.7.3.0 of mori://shinzui/kiroku/packages/kiroku-store-migrations appends `0017`,
which needs a separately reviewed schema upgrade. This window retains the
63-entry plan: 16 Kiroku, 32 Keiro and 15 Kioku. Historical Kioku SQL, checksums
and catalog identities are preserved; this edge authorizes source edits only.

For hosts that construct or pattern-match Baikai values directly, inspect the
released upstream changes. `ThinkingLevel` gains `ThinkingNone`; content and
event sums gain structured-data alternatives, and compatibility/model/error/
trace records gain fields. Prefer exported default records and constructors.
Search exhaustive matches on `ThinkingLevel`, `AssistantContent`, `UserContent`
and provider events. Preserve `Nothing` as the absent reasoning preference;
`ThinkingNone` explicitly requests reasoning off. Keep the host's AI authority,
registries and per-feature permissions explicit.

Resolve and build the consumer with these project settings. Test its own AI
dispatch, response serialization/replay and any direct Baikai integrations.
Kioku's 500 passing tests cover Kioku's paths, including explicit reasoning off
and structured assistant response serialization; they do not establish every
consumer's upstream API compatibility. Report the resolved versions and tests.

This edge declares no upstream entailment: the Baikai and Shikumi repositories
have no corresponding declared upgrade blueprint to reference at authoring time.
